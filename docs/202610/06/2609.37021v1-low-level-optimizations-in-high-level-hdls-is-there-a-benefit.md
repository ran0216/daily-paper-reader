## 摘要
本文探讨函数式编程在专用集成电路（ASIC）设计中的适用性。我们研究了使用高层次、抽象的硬件描述语言（HDL）特性设计ASIC，与采用底层优化相比，对综合后电路面积的影响。目的是确定使用底层优化是否有益；如果有益，是否值得为此增加实现工作量。为开展该研究，我们使用函数式HDL Clash，以16种不同配置实现了一个无符号位串行乘累加（MAC）单元。我们既利用了底层位操作技术，也利用了Clash用于电路设计的高层构造。实验评估表明，Clash的某些高层构造对所得电路规模的影响可忽略不计，这表明充分利用函数式编程的能力是一种可行的硬件设计方法。为评估所用HDL本身的影响，我们还用Verilog实现了MAC的若干版本。实验清楚表明，与经验丰富的工程师编写的Verilog代码相比，使用Clash似乎存在固有开销。

## 速览
**TLDR**：面向 ASIC 设计，论文探究在函数式 HDL Clash 中采用高层抽象与底层优化对综合面积的影响。作者实现 16 种配置的无符号位串行 MAC，混合使用位操作与 Clash 高层构造，并用 Verilog 版本作对照。结果表明，部分 Clash 高层构造对电路规模影响可忽略，函数式编程可有效用于硬件设计；但相比资深工程师手写 Verilog，Clash 仍带来固有开销。该工作量化了底层优化的收益与实现代价，并评估其是否值得增加实现工作量，为高层 HDL 的工程取舍提供依据。 \
**Motivation**：探究高层 HDL 中底层优化是否必要，以及函数式编程用于 ASIC 设计能否兼顾抽象与面积。 \
**Method**：用 Clash 实现 16 种配置的无符号位串行 MAC，混合底层位操作与高层构造，并编写 Verilog 版本对照。 \
**Result**：部分 Clash 高层构造对电路面积影响可忽略；但 Clash 相比资深工程师手写 Verilog 仍存在固有开销。 \
**Conclusion**：高层函数式 HDL 设计可行，但底层优化收益需权衡；Clash 相对 Verilog 的开销提示工程选用需谨慎。

## Abstract
This paper explores the applicability of functional programming to the design of Application-specific Integrated Circuits (ASICs). We investigate the impact of designing ASICs using high-level, abstract Hardware Description Language (HDL) features versus employing low-level optimizations on the area of the synthesized circuits. The aim is to determine whether using low-level optimizations is beneficial and, if so, whether it is worth the added implementation effort.   To carry out the investigation, we implement an unsigned bit-serial multiply-accumulate (MAC) unit in 16 different configurations using the functional HDL Clash. We make use of both low-level bit-manipulation techniques as well as Clash's high-level constructs for circuit design. The experimental evaluation shows that some high-level constructs of Clash have negligible influence on the resulting circuit size, suggesting that using the full power of functional programming is a viable approach to hardware design. To evaluate the impact of the used HDL itself, we also implemented versions of the MAC in Verilog. The experiments clearly show that there seems to be an inherent overhead in using Clash compared to Verilog code written by a seasoned engineer.
