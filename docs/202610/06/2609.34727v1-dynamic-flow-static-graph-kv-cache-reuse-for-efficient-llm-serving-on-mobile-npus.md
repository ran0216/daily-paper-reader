## 摘要
端侧大语言模型（LLM）服务是本地优先个人智能的基石，为用户提供数据主权、强隐私保障，并摆脱云 API 的延迟与成本。尽管 KV 缓存被广泛用于降低长上下文推理延迟，但现有设计主要针对具有动态执行环境和充足内存带宽的云端 GPU 进行优化。这些架构假设在移动 NPU 上并不成立：计算图必须静态编译，且内存容量与 I/O 带宽都受到严重约束。在本工作中，我们提出一种面向移动端的计算-存储协同设计，用于前缀与非前缀 KV 复用。我们首先提出一种图内机制，将选择性 KV 重计算映射到静态 NPU 图上，从而调和算法动态性与 NPU 静态性。我们进一步开发一种图间调度器，利用动态规划优化块合并并最小化填充。为应对移动带宽限制，我们引入一种分层 KV 管理器，其具备树-哈希-语义混合结构，以及成本感知的预取与驱逐策略。我们还构建了一个二维流水线，将 KV 加载、重旋转（rerotation）和存储与 NPU 执行重叠，从而隐藏数据移动延迟。在代表性端侧工作负载和 LLM 上的实验表明，与不复用和仅前缀缓存相比，我们的设计将首 token 时间（TTFT）降低了 40-60%。

## Abstract
On-device large language model (LLM) serving is a cornerstone of local-first personal intelligence, offering users data sovereignty, strong privacy guarantees, and freedom from cloud API latency and cost. Although KV caching is widely used to reduce latency in long-context inference, existing designs were primarily optimized for cloud GPUs with dynamic execution environments and abundant memory bandwidth. These architectural assumptions do not hold on mobile NPUs, where computation graphs must be statically compiled and both memory capacity and I/O bandwidth are severely constrained. In this work, we present a compute-storage co-design for mobile-centric prefix and non-prefix KV reuse. We first propose an intra-graph mechanism that maps selective KV recomputation onto static NPU graphs, reconciling algorithmic dynamicity with NPU staticity. We further develop an inter-graph scheduler to optimize chunk merging and minimize padding with dynamic programming. To address mobile bandwidth limitations, we introduce a hierarchical KV manager featuring a tree-hash-semantic hybrid structure, along with cost-aware prefetching and eviction policies. We also build a two-dimensional pipeline that overlaps KV loading, rerotation, and storage with NPU execution, hiding data-movement latency. Experiments across representative on-device workloads and LLMs show that our design reduces time-to-first-token (TTFT) by $40-60\%$ compared with no reuse and prefix-only caching.

## 1. 核心问题与研究动机

- **背景**：端侧 LLM 服务是"本地优先个人智能"的基础，具备数据主权、隐私保护、离线可用与低延迟等优势。代表性应用（Gemini 个性化、Apple Intelligence 端侧 3B 模型、ClawMobile、OmniInfer）都依赖设备本地推理。

- **核心痛点**：prefill 延迟即 TTFT 随 prompt 长度近似线性增长，超过 2k token 即达数秒；同等长度下移动 NPU 比云端 GPU 慢 **2–5×**。
- **已有方案的错配**：云端 KV 复用方案（Mooncake、RAGCache、LMCache、CacheBlend，以及 vLLM/SGLang 中的集成）面向 GPU 动态执行环境与充裕带宽；而端侧引擎（ExecuTorch、MLC-LLM、llama.cpp、MediaPipe）几乎不支持跨请求持久 KV 复用、分层管理和非前缀复用。
- **两个结构性挑战**：
  - **重计算动态性 vs. NPU 静态性**：选择性 KV 重计算引入 5 类动态性（输入形状、重计算选择、数值范围、末 token 输出、复用模式），而移动 NPU 要求离线预编译的固定形状静态图，并偏好静态量化与 INT GEMM。
  - **KV 体积大 vs. 带宽/容量受限**：如 Qwen3-1.7B 的 8-bit KV 每 token 约 56 KB，1024 token 约 56 MB，在 Xiaomi 15 Pro 上从 flash 加载约需 200 ms，若不能隐藏将抵消 NPU 优势。

## 2. 方法论

### 2.1 整体思想
计算-存储协同设计（compute-storage co-design）：在计算侧把动态 KV 复用算法"静态化"为 NPU 可执行的预编译图，在存储侧构建分层 KV 管理与流水线重叠，使 KV 复用真正在移动端可用。

### 2.2 图内机制（§4.1，将动态算法映射到静态图）
- **Chunk–Pad–Mask**：把非前缀 token 切分为固定长度切片，不足则 padding；计算 KV 偏差前施加 valid mask，排除 padding token 被 Top-K 误选，并**强制选中最后一个 token**以正确产生 logits。
- **Scatter–Gather**：Top-K 选出高偏差 token 后，重算其 KV 并 scatter 回被复用的 KV cache，替换对应条目，兼顾动态选择与静态图结构。
- **图尺寸优化**：prefill 图尺寸 $L_P$ 与选择性重算图尺寸 $L_S$ 通过最小化代表性负载上的期望延迟确定，$\text{Latency}_G(n)=\lceil n/L_G\rceil\cdot \text{Latency}_G(L_G)$，再按 token 长度频率加权求期望；尺寸限制为 32 的倍数以对齐 Qualcomm HMX tile。
- **混合精度量化**：KV 用 SpinQuant INT8、权重 INT4、多数中间激活 UINT16；但**精度敏感的 KV 偏差计算与 Top-K 比较保留 FP16**，并乘以 $1/\sqrt{D_{head}}$ 缩放因子防止 FP16 溢出，避免静态量化导致的精度塌陷。

### 2.3 图间调度（§4.2，动态规划块合并）
- 关键洞察：**新 token 可以安全地由选择性重算图处理**（它们总会被选中计算），因此可把相邻欠填充的图调用合并。
- 动态规划转移：$T[i]=\min\{T[i-l_s(i)]+t_s,\ T[i-l_p(i)]+t_p\}$，其中 $l_s(i)$ 为在重算图容量与最小重算比例 $r$ 约束下可吸收的最长后缀（可含有限新 token，新 token 每 $\lceil \Delta/r\rceil$ 消耗容量），$l_p(i)$ 为 prefill 图可打包的最长后缀。
- 效果：避免按 token 类型朴素切分造成的碎片化与 padding 浪费；示例中 prefill 图调用从 4 次降至 2 次，约减少 25% 延迟。

### 2.4 分层 KV 存储（§5）
- **三级结构**：NPU KV Manager（CPU–NPU 共享 buffer，约 10¹ MB）→ CPU KV Pool（约 10² MB，轻量哈希表，按 DB row ID 索引）→ Flash KV DB。
- **Flash 混合索引**：前缀树（支持前缀复用与层级组织）+ 64-bit 哈希码（非前缀精确块匹配）+ 轻量语义索引（关键词稀疏嵌入、必要时复用 RAG 已有稠密嵌入），再用**线性时间 LCS（后缀自动机 + 稀疏转移）**在候选块中确定可复用子串。
- **存储工程优化**：KV 张量不直接作为 SQLite BLOB 内嵌，而由 SQLite 仅存元数据（key、prompt hash、局部性统计、文件路径），张量以独立文件写入文件系统，避免页级碎片与写放大。
- **预取与淘汰**：局部性评分 $R(c)=w_sR_s+w_tR_t+w_mR_m$（空间/时间/语义）；淘汰按 $R(c)\cdot C(c)$ 排序，并区分层级成本：CPU pool 中非前缀块的驱逐成本近似为 0（加载可被重叠隐藏），flash 中需计入重算成本 $\text{Latency}_P(|c_i|)$ 与**破坏前缀链导致的级联成本** $C_{cascade}=\sum_{c_j\in Des(c_i)} f(c_j)\cdot \text{Latency}_S(|c_i|)$。

### 2.5 计算-存储流水线（§6）
- **IO–CPU–NPU 重叠**：KV 加载（I/O 密集）与 RoPE 重旋转（含 SpinQuant 的 Hadamard 变换、反量化/重量化，内存密集）放在 CPU 异步执行，与 NPU 计算并行。
- **Chunk–Shard 二维流水线**：NPU 按模型 shard 执行、prompt 按 chunk 处理，沿两维流水，使数据准备延迟对 NPU 执行"不可见"（shard 级并行使加载延迟降低 4×）。
- **异步懒持久化**：新生成 KV 先在 CPU pool 标记 dirty，空闲时后台批量落盘，KV 存储可与解码重叠。

## 6. 主要结论与发现

- **TTFT 显著下降**：相对 no reuse 实现 1.5×–5.4× prefill 加速，相对 prefix caching 为 1.3×–2.5×；总体 TTFT 降低 40%–60%（HotpotQA 32–56%、LoCoMo 42–65%、SkillsBench 68–81%）。
- **质量损失可忽略**：相比 no reuse，准确率下降 ≤4%；而 full reuse 约损失 30% 精度，且仅比本方案快约 12%（因重旋转开销暴露在关键路径）。
- **能耗同比例下降**：平均功耗与 no reuse 相当（6.34 W vs. 6.68 W），prefill 能耗降低 52%（HotpotQA）、67%（LoCoMo）、77%（SkillsBench）。
- **敏感性规律**：前缀复用收益最大（3072 token、75% 复用率时降低 67.4–78.3% 延迟；100% 复用率时降低 94.1–99.7%）；非前缀复用 100% 时降低 44.9–67.9%，残余延迟主要来自选择性重算开销，但整体仍远优于全量 prefill。
- **组件贡献**：全系统配置下 NPU 执行占 TTFT 95% 以上，说明复用开销基本被
