## 摘要
粗粒度可重构阵列（CGRA）是在各种应用领域实现高能效和可重构性的有前途的解决方案，但其性能常常由于僵化的存储器架构而受到严重限制，该架构限制了可访问数据存储器的瓦片的数量和位置。这对于具有密集存储器访问的内核来说造成了显著的瓶颈。为了解决这个问题，我们提出了CMD，一种集成的CGRA框架，具有基于集群的分布式存储器设计和协同设计的编译工具链。编译器包含一种新颖的存储器感知映射器和一个设计空间探索（DSE）机制，该机制为特定内核识别最佳的存储器架构设计。实验结果表明，我们经过DSE后的CMD CGRA平均速度是传统CGRA的$1.39\times$，同时将总面积平均降低到传统CGRA的$0.912\times$。

## Abstract
Coarse-Grained Reconfigurable Arrays (CGRAs) are a promising solution for achieving high energy efficiency and reconfigurability across various application domains, but their performance is often crippled by rigid memory architectures that limit the number and location of tiles that can access data memory. This creates a significant bottleneck for kernels with intensive memory accesses. To address this, we propose CMD, an integrated CGRA framework featuring cluster-based distributed memory design with a co-designed compilation toolchain. The compiler includes a novel memory-aware mapper and a design space exploration (DSE) mechanism that identifies the optimal memory architecture design for specific kernels. Experimental results show that our post-DSE CMD CGRAs achieve an average speedup of $1.39\times$ over a conventional CGRA while simultaneously reducing the total area to an average of $0.912\times$ of the conventional CGRA.

## 1. 核心问题与整体含义（研究动机与背景）

- **CGRA 的基本定位**：粗粒度可重构阵列（CGRA）由通过片上网络（NoC）互联的计算瓦片（tile）阵列构成，在高能效和可重构性之间取得平衡，被广泛部署于高性能计算（HPC）和机器学习（ML）等领域的加速任务。编译器的目标是将应用中性能关键的循环核（kernels）转换成数据流图（DFG）并映射到CGRA上，从而**最小化启动间隔（II）**。
- **核心痛点（集中式存储瓶颈）**：现有大多数CGRA采用紧邻瓦片阵列的**集中式全局数据存储器**，访问方式主要有两种：
  - **瓦片访问法（tile-based）**：仅固定少数（如最左列/最上行的）瓦片可访问数据存储器，其他瓦片所需数据必须跨阵列中继转发，导致严重布线压力。
  - **硬件/软件仲裁法（HW/SW arbitration）**：每行/列每周期仅允许一个瓦片访问存储器，同组瓦片产生访存冲突时需竞争仲裁。
  - **后果**：这两种机制都从根本上限制了可访问存储器的瓦片**数量与方位**，由此引入“布线路由约束”，直接引发两大性能瓶颈：
    1. **II 被拉长**：理论最小II（MII）未能反映布线约束。存储器访问操作被迫排队等待有限的访存资源，阻塞依赖它们的运算，导致编译结果无法达到MII（示例中从最佳4增加到5）。
    2. **计算效率低下**：大量瓦片被浪费于纯数据中继转发（示例中多周期内相当比例瓦片只做数据传输），计算效率定义中高传输瓦片数（`N_itr`）导致效率显著下降。阵列规模越大，离存储器越远的瓦片需要更多中继步骤，问题越严重。
- **研究含义**：作者认为，解决集中式存储瓶颈需要**范式转换**：走向分布式存储架构，并协同设计编译框架以充分利用之。该工作由此出发，提出CMD框架，是首个将分布式存储架构的设计融入“时空型（spatio-temporal）CGRA”的工作。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 总体框架架构
- **系统结构**：CMD CGRA作为与CPU松散耦合（loosely coupled）的加速器运行；DMA单元负责在配置阶段加载数据到各个分布式存储单元及初始化存储器控制器。
- **瓦片互连**：瓦片间采用Mesh-style拓扑；每个瓦片包含支持LLVM IR运算的功能单元、控制存储器、6×12交叉开关、8组寄存器文件和4个旁路缓冲器。

### 2.2 基于集群的分布式存储器架构
- **集群划分**：CGRA阵列被划分为若干集群，一组瓦片共享一个专用本地存储单元。各瓦片仅可访问自己所在集群的存储单元。文中评估了6×6阵列下的集群大小（cluster size）为{1, 2, 4, 6}。
- **存储单元内部组成**：每个存储单元由多bank数据存储器（bank数量与集群瓦片数匹配，支持同一集群内各瓦片同时访问）、访存仲裁器（arbiter）和缓存一致性模块构成。
- **内存一致性控制器**：引入实现MESI类协议的内存一致性控制器，通过一个记录各变量实例状态的`varInfoTable`来追踪分布式存储单元间的数据同步。
  - **具体流程**：存储单元内的一致性模块检测到写操作后，发送包含变量名、所写索引、新值等信息的分组（28×4 bit）至控制器。控制器采用**四步、两周期**流程处理：周期1中信息分发器更新`varInfoTable`（标记修改/失效状态），并向共享副本所在存储单元广播失效信号；周期2中一致性管理器识别失效实例、生成同步请求并把对应各副本状态更新为共享（S），最终更新目标存储单元的本地数据。
  - **两周期设计的权衡**：单周期实现会降低系统频率，更长延迟会损害性能，两周期方案取得平衡。

### 2.3 编译工具链与EDFG/EMRRG抽象
- **DFG构建**：从应用提取内层循环，利用部分谓词（partial predication）将控制依赖转化为数据依赖并构造DFG。
- **EDFG构建（核心创新之一）**：将DFG扩展为EDFG——为每个访存操作显式建模**变量节点**。每个变量节点记录变量名称、大小、数据类型、关联访存操作和唯一变量ID等元数据。同一变量被多个操作访问时，初始表示为多个不同变量节点，从而赋予映射器“同一变量分布存储在不同存储单元中”的布局灵活性。对于超大型变量，编译器采用循环分块（tiling）将其切分以适配存储单元容量。
- **EMRRG抽象**：在传统MRRG基础上，加入存储架构信息，形成EMRRG。

### 2.4 内存感知映射算法（Algorithm 1）
- 算法将EDFG映射到EMRRG，核心是以最小II为目标。整体流程：
  1. 基于数据依赖递归（RecMII）与计算资源（ResMII）约束计算最小II初始值并进入外层循环——映射失败时自增II；
  2. 按当前II生成EMRRG，按拓扑序遍历EDFG中的每个操作节点；
  3. 对每个操作节点遍历所有可用瓦片，**对访存操作额外加入两类约束检查**：每条访存规则（见下文）必须被满足；检查变量在目标存储单元中是否已存在；检查存储单元是否溢出；
  4. 用深度优先搜索（DFS）计算各候选瓦片的映射代价，选取代价最小的瓦片完成放置与布线（place & route）。
- **变量节点合并机制**：在放置访存操作前，检查变量是否已存在于目标存储单元中，若是则合并新变量节点以避免冗余存储；否则须确认存储单元有足够剩余空间。
- **内存一致性映射规则**（保证正确性的两条规则）：
  1. 因为一致性控制器需要两周期完成同步，任何变量被修改后的两周期内不允许其他操作再访问该变量，防止读取到过期数据；
  2. 当同一变量存储于多个存储单元时，同一周期限制对该变量同一索引最多执行一次写操作，避免并发写冲突。
  - 消融实验（ablation study）表明：在测试基准中，移除这些规则对延迟几乎无影响——规则1的开销可被调度其他独立操作隐藏；规则2只用于保证正确性、不产生性能影响。

### 2.5 存储架构设计空间探索（DSE）
- **方法**：采用**网格搜索（grid search）**，因设计空间较小（集群大小×存储单元大小），可在数分钟内完成搜索。输入为一组来自特定领域或应用的内核。
- **成本函数**：多目标优化化为单一成本函数，对M个输入内核取平均：
  - **cost** = (1/M) × Σ_k ( w1 × II_k + w2 / COR_k + w3 × C_total,k )
  - 其中权重设为 **w1 ≫ w2 ~ w3**，即优先保证性能（最小II），同时惩罚过大的存储开销。
- **搜索范围**：无合法设计时增大CGRA阵列尺寸直到找到合法映射。

- **性能与面积**：后DSE的CMD CGRA相对基线平均加速**1.39×**（最高1.63×，对应2mm），同时将总面积降至基线的平均**0.912×**，实现了**同时提升性能和缩减面积**。

- **计算效率**：后DSE架构平均计算效率40.0%（最高51.0%），比基线提升约1.27×，确证分布式存储释放了更多瓦片做实际计算而非数据中继。
- **内存利用指标**：
  - 后DSE的平均MUR（存储单元使用率）达67.2%（最高100%），较预DSE平均提升1.70×；
  - 平均COR（占用存储单元容量利用率）达66.1%（最高98.2%），较预DSE平均提升2.34×；

- **控制器扩展性**：6×6除去的存储器控制器面积仅为0.00187 mm²（约占瓦片总面积的0.736%），且随着阵列增大（16×16）归一化开销持续下降（0.238%），证明一致性控制器设计可扩展到大规模CGRA。
- **验证核心主张**：路由约束被成功缓解，映射可达到理论最小II（如gemm、trVecAccum案例），存储架构与编译协同设计是一条有效释放CGRA计算潜能的关键路径。

## 7. 优点与亮点

- **架构与编译协同设计（co-design）**：不局限于硬件端存储布局改进，而是在同一框架内设计编译器映射算法保证硬件能力真正可被利用，并配套DSE自动求最优参数。
- **EDFG/EMRRG抽象新颖且实用**：将变量显式建模进数据流图，让映射器可直接感知访存的位置与容量约束，为分布式存储的变量放置提供编译期精确决策。
- **轻量有效的硬件一致性机制**：用MESI式两周期四步控制的专用控制器维护多存储单元数据同步，保证在极小硬件开销（面积仅占总体0.5%）下实现分布式共享变量的正确性。
- **规则策略与映射算法有机结合**：将“写后同步保护窗”“单周期单索引单写”等一致性关键约束在编译映射阶段静态满足，降低了硬件复杂性并提升调度可预测性。
- **DSE面向多目标**：采用带权成本函数设定主次目标，明确承认权衡本质，并通过实验案例表明在II、COR、总存储大小之间可调耦合、按需配置，体现了良好的灵活性。
- **扩展性分析扎实**：对多阵列大小的控制器做了额外综合与面积分析，加强对实际部署可行性的论证。

## 8. 不足与局限

- **缺乏真实硬件（流片/FPGA）验证**：所有性能与功耗面积数据依赖周期精确模拟器与RTL综合，缺少对片上真实运行性能、同步延迟等物理效应的实测确认。
- **未量化计算资源成本**：论文未披露整体实验占用的CPU计算量、所需集群规模或每轮DSE的具体耗时预算，影响复现与资源评估。
- **研究内核规模较有限**：benchmark的运算规模（trip count）较小、变量总大小大多在KB级，对更大输入、更复杂数据依赖模式和多种存储访问模式（如随机访存、稀疏访问）的适应性有待验证。
- **DSE搜索空间约束明显**：仅枚举集群大小与存储单元大小两个维度，未联合搜索阵列规模、NoC拓扑、bank数、调度粒度和可变存储映射策略等更大范围的设计参数；基于成本函数加权方法也天然无法实现帕累托多目标同时最优。
- **一致性机制的潜在性能风险**：两周期同步窗口假设在“写传播密集/多存储单元频繁共享同一变量”的负载中可能造成较大乘性开销；论文并未针对高频共享变量的压力场景做专项压力测试。
- **对比基线较为单一**：仅对比传统集中式CGRA同源映射器，未与已有的仲裁访存CGRA、其他分布式CGRA（如Plasticine/versal AIE风格设计）进行定量基准比较。
- **计算效率定义的局限**：公式将“纯传输瓦片”全部视为浪费，但某些应用中中继路径是不可避免的且承担同步/延迟匹配功能，可能高估了CMD的效率优势。
