## 摘要
功耗分析在现代芯片设计流程中至关重要。特别是基于时间的功耗分析能够提供细粒度的功耗信息，有助于诊断功耗问题并指导相应的功耗优化。然而，对现代大规模电路进行基于时间的功耗分析可能需要数十小时，这大大减慢了功耗优化流程。本文提出了首个GPU加速的门级时域功耗分析框架。我们提出了一种新颖的数据结构，以实现高效的状态相关功耗检索。为了适应门之间不平衡的事件分布，我们提出了一种事件密度感知的分区策略，根据门事件密度分配GPU线程。最后，我们将功耗计算融合到单一内核调用中，以减少独立内核中的冗余工作。实验结果表明，与多线程Synopsys PrimeTime PX相比，我们提出的框架在实现高精度的同时，提供了高达37.63倍的端到端加速。

## Abstract
Power analysis is crucial in modern chip design flow. Particularly, time-based power analysis can provide fine-grained power consumption information to facilitate the diagnosis of power issues and guide power optimization accordingly. However, it may take tens of hours to conduct time-based power analysis on modern large-scale circuits, which greatly slows down the power optimization flow. In this paper, we present the first GPU-accelerated gate-level time-based power analysis framework. We propose a novel data structure to enable efficient state-dependent power retrieval. To accommodate the imbalanced event distribution across gates, we propose an event-density-aware partitioning strategy that allocates GPU threads based on gate event density. Finally, we fuse the power computation into a single kernel invocation to reduce redundant work in separate kernels. Experimental results show that our proposed framework achieves high accuracy while delivering up to 37.63x end-to-end speedup compared to multi-threaded Synopsys PrimeTime PX.

## 一、论文核心问题与整体含义（研究动机与背景）

功耗已成为现代 VLSI 系统设计中的首要约束，直接影响性能、热管理和可靠性。**基于时间的（time-based）功耗分析**能提供细粒度的功耗信息（如逐事件、逐周期的变化），对于诊断功耗热点与瞬态问题、指导功耗优化至关重要。

然而，现有门级时域功耗分析面临严重的计算瓶颈：

- **大规模电路耗时极长**：例如对一个 288k 门的电路进行分析可能需要数天，严重拖慢功耗优化迭代流程。
- **现有方法各有缺陷**：
  - **基于机器学习（ML）的方法**（如 PRIMAL、GRANNITE 等）通常将功耗分析建模为基于 RTL 活动代理的估计问题，不执行真实的逐事件、逐门功耗累加，缺乏物理根基，难以保证精确的时域结果。
  - **基于仿真的方法**（如 Strober、SMART-GPO）多采用采样或有限时域覆盖，可能遗漏短时毛刺（glitch）和瞬态峰值功耗。
  - **商业工具**（如 Synopsys PrimeTime PX）支持完整精密的门级时域功耗分析，但在大型设计上运行时间过长，成为设计流程的瓶颈。

该论文的核心目标即在于：**利用 GPU 的大规模并行能力，加速门级时域功耗分析，同时保持与商业工具相当的高精度**，从而解除这一计算瓶颈。文章声称是首个在 GPU 上探索完整门级时域功耗分析的工作。

## 二、提出的方法论：核心思想、关键技术细节

### 总体架构

文章提出了一套完整的 GPU 加速门级时域功耗分析框架，采用 **CPU 预处理 + GPU 并行计算**的异构流水线：

- **CPU 端**：设计/模型解析（.gv、.spef、.sdc、.lib），STA 时序分析，活动文件解析（.fsdb/.vcd），事件分块与打包。
- **GPU 端**：功耗计算的并行执行（融合功耗计算内核 + 归约内核），支持动态功耗、漏电功耗、毛刺功耗以及逐周期功耗波形。

### 三大关键技术

针对 GPU 加速时域功耗分析的三个核心挑战，文章分别提出三项技术：

#### 1. 状态索引功耗查找（SIPL, State-Indexed Power Lookup）

- **挑战**：传统的状态相关功耗检索需要每次事件进行两次迭代列表遍历（分别查漏电和内部功耗表），复杂度为 O(n(pin)·n(sd))，耗时严重。
- **方法**：将门状态模式进行**二进制编码**（各引脚按固定顺序对应一个比特位），以编码后的整数直接作为功耗检索数组的下标，将查找复杂度降为 O(n(pin))。
- **细节**：
  - 对 Liberty 文件中的每个状态模式，枚举其"不关心（don't-care）"引脚的赋值，填充对应的所有数组项。
  - 对于引脚超过 16 个的门（如 SRAM 宏，可达上百引脚），直接建表会内存爆炸（2^100），故仅对 ≤16 引脚的门使用 SIPL，其余门回退到原始状态模式遍历。实验中有 34.976% 的门（阈值由4提高到16后平均仅0.05%）会走回退路径，但总体开销很小。

#### 2. 事件密度感知的自适应逐门分区（Event-Density-Aware Per-Gate Partitioning）

- **挑战**：门间事件分布高度偏斜（如图 4 所示，p50 至 p99 事件数可差 4 个数量级），全局固定分区粒度（固定每线程周期数）无法适应不同门的负载差异——粒度太细会导致稀疏门过度并行化（大量空闲线程），粒度太粗会限制密集门的并行度。
- **方法**：为每个门 $g$ 根据其**平均事件密度** $\rho^{(g)} = N^{(g)}_{evt}/N_{cyc}$ 自适应地确定每线程周期数 $n^{(g)}_{cyc}$。
- **参数控制**：引入每线程目标事件数 $n_{evt,tgt}$ 和并行度下限 $N_{thr,floor}$（对应密度下限 $\rho_{floor}$），合并为有效密度 $\rho^{(g)}_{eff} = \rho^{(g)} + \rho_{floor}$，最终每线程周期数取 $n^{(g)}_{cyc} = \mathrm{round}(n_{evt,tgt}/\rho^{(g)}_{eff})$。
- **效果**：推导表明线程数近似为 $N^{(g)}_{thr} \approx N^{(g)}_{evt}/n_{evt,tgt} + N_{thr,floor}$。稀疏门受下限约束避免过度并行化，密集门则按事件数获得更多线程，实现了负载均衡且避免不必要的线程调度开销。

#### 3. 内核融合（Kernel Fusion）

- **挑战**：动态功耗（Naive-D）与漏电功耗（Naive-L）分别在不同内核中计算会导致冗余工作：(a) 两内核各自执行昂贵的门状态重建（跨引脚二分搜索）；(b) Naive-D 做毛刺检测所需的周期事件计数信息在 Naive-L 的周期遍历中已暴露，未加复用。
- **方法**：将动态与漏电功耗计算融合到**单个内核调用**中，每个线程按事件时间戳排序进行 $k$ 路归并：
  - 状态只在窗口开始时重建一次，此后逐步增量更新；
  - 漏电功耗在相邻事件间隔内取值恒定，逐段累加并按周期切分写入波形；
  - 动态功耗在每次事件发生后按状态查询内部功耗 LUT 并计算开关能量；
  - 毛刺检测通过维护每引脚的周期事件计数器实现，与周期级信息共享，避免重复二分搜索。

### 其他工程实现要点

- **线程映射与两阶段归约**：一个线程处理某个门的一段连续周期窗口；为节省显存，采用"线程块内原子累加至每门归约缓冲矩阵 R^(g) ∈ R^(N_tpb × 4) + 独立归约内核串行累加"的两阶段策略。
- **流水线执行**：CPU 端事件打包与 GPU 端功耗计算重叠，逐事件块迭代处理。

## 六、主要结论与发现

1. **精度高**：与 PrimeTime PX 相比，漏电、内部、开关、毛刺、峰值功率的平均误差分别仅 0.12%、0.06%、0.05%、0.11% 和 0.71%；逐门总功率 Kendall's Tau ≥ 0.994（毛刺 ≥ 0.998）；热点重合度和逐周期波形相关性都很高。
2. **加速比显著且随规模增大而提升**：端到端加速比 1.94×~37.63×。在较小设计（Adder、Multiplier）上收益有限；在大型 SoC 上加速明显（如 SmallBOOM mt-vvadd 上 37.63×，GigaBOOM 上 33× 左右），说明本文方法能有效突破大规模时域功耗分析的计算瓶颈。
3. **瓶颈转移**：GPU 加速后，功耗计算不再是主要瓶颈（CPU 流程占比 76.3% → GPU 流程仅占 8.27%），活动文件解析成为最大开销（68%）。
4. **各项优化均有效**：
   - SIPL 带来几何平均 9.45% 的 kernel 时间缩减（单独增量的贡献），从完整方案中移除则增慢 23.4%；
   - 事件密度感知分区是最有效的优化，单独增量缩减 43.67% 的 kernel 时间，移除则增慢 147.4%（最高达 275.9%）；
   - 内核融合带来 63.12% 的增量缩减，移除则增慢 52.9%。
5. **内核瓶颈是访存延迟而非计算/带宽**：Nsight 分析显示低 occupancy（~37.67%，理论最高 41.67%）与长延迟依赖（Long Scoreboard 占 stall 的 49%~60%）是主导因素，受寄存器占用限制。
6. **跨平台可移植性良好**：在 A30（延迟约 1.6×）和 H100（加速约 1.8×）上表现出与硬件能力一致但非线性的性能趋势，进一步印证访存延迟限制的判断。

## 七、优点

1. **问题选得好且具有实用性**：针对时域功耗分析这个工业界真实痛点（耗时数十小时），给出有效解法。
2. **首个 GPU 时域功耗分析方案**：在该细分领域具有开创性。
3. **核心洞察清晰深入**：对三个 GPU 加速挑战（状态检索慢、事件分布不均衡、内核间冗余）的刻画基于扎实的测量数据（如事件分布 p50/p99 统计）；
4. **三项优化技术针对性强**：
   - SIPL 是工程上简洁高效的技巧——用空间换时间，将 O(n·m) 遍历转成 O(1) 查表，且带 16 引脚阈值控制内存风险；
   - 事件密度感知的分区有理论推导支撑（线程数上界/下限可控），对偏斜负载问题对症下药；
   - 内核融合不只是"减少启动开销"，而是结构性复用了状态重建和毛刺检测所需的周期级信息。
5. **实验全面、精度对比细致**：从整体到逐门到逐周期，多维度验证与商业工具的一致性，误差小，证据充分。
6. **考虑工程落地细节**：显存分块流水（事件分块）、两阶段归约、CPU-GPU 重叠流水、参数灵敏度分析等都让方案更接近实际可用；
7. **开源**：代码公开（GitHub: GTPower），对后续研究有较大价值。

## 八、不足与局限

1. **无同类 GPU 方法对比**：由于领域空白，只能对比商业 CPU 工具和自己的 Naive GPU 实现，缺少与同类并行方案的横向比较。
2. **设计规模覆盖有限**：最大验证设计为 105 万门，与工业界的数千万至上亿门全芯片相比仍有较大差距；事件数/显存的可扩展性在更极端的工业场景下尚需验证。
3. **技术选择限制**：
   - SIPL 需将引脚状态表示为二进制索引，对引脚过多的单元必须回退遍历策略（虽仅 0.05% 的门受影响，但这类门可能是特殊的存储宏等关键单元）；
   - 毛刺检测采用"一周期内超过一个事件即算毛刺"这种时钟周期级简化方法，与商用工具的精度设置一致，但对亚周期级精确时域分析不足；
   - 内部功耗 LUT 插值采用 NLDM 模型，对更先进工艺下的电流源模型（CCS/ECSM）支持不足。
4. **GPU 占用率与显存**：
   - 融合内核寄存器占用（89/线程）使理论占用率仅 41.67%，实验中发现通过限制寄存器提升占用率反而显著降低性能，说明该方案对延迟隐藏的利用受限；
   - 峰值显存 12.22~15.44 GB，其中事件存储占 77.2%~97.5%，对于更长仿真波形或更大设计可能超出单卡显存，需要重复分块传输，产生额外开销。
5. **预处理成为新瓶颈**：GPU 加速后活动文件解析占端到端时间达 68%，论文并未针对这一环节做深度加速，整体加速比被文件解析拖累。
6. **通用性验证不足**：
   - 实验仅采用 TSMC N28 工艺；
   - 未比较不同工艺角（PVT corner）；
   - 未与其他开源工具（如 OpenSTA 的功耗模式）做对比验证。
