## 摘要
晶圆级GPU（WSG）提供了足够的片上带宽，使近无损的统一内存变得可行。然而，现有设计仍依赖CPU-IOMMU来翻译远程虚拟地址访问。这种集中式机制在扩展到数十个GPU裸片时性能不佳：翻译请求必须穿越代价高昂的片外层级，并争用有限的CPU侧资源，使地址翻译成为关键瓶颈。我们提出了WaferTrans，一种面向WSG的无IOMMU分布式虚拟地址翻译设计。WaferTrans引入了PTE存在性一致性（PTE-PC），一种轻量级一致性模型，用于跟踪PTE的插入和移除，并为每个GPU配备一个PTE存在性目录（PPD），以定位持有请求PTE的GPU。它进一步采用分布式PTE-PC映射和协作查询机制，在保持完整查找覆盖的同时本地化PTE-PC维护。这些机制共同使GPU阵列能够在晶圆内解析远程翻译，从而消除其对CPU-IOMMU的依赖。与最先进的Trans-FW设计相比，WaferTrans平均性能提升了2.5倍。

## Abstract
Wafer-scale GPUs (WSGs) provide sufficient on-wafer bandwidth to make near-lossless Unified Memory feasible. However, existing designs still rely on a CPU-IOMMU to translate remote virtual-address accesses. This centralized mechanism scales poorly to tens of GPU dies: translation requests must traverse costly off-wafer hierarchies and contend for limited CPU-side resources, making address translation a critical bottleneck. We propose WaferTrans, an IOMMU-free distributed virtual-address translation design for WSGs. WaferTrans introduces PTE Presence Consistency (PTE-PC), a lightweight consistency model that tracks PTE insertions and removals, and equips each GPU with a PTE Presence Directory (PPD) that locates the GPU holding a requested PTE. It further employs a distributed PTE-PC mapping and a cooperative query mechanism to localize PTE-PC maintenance while preserving complete lookup coverage. Together, these mechanisms enable the GPU array to resolve remote translations within the wafer, eliminating its dependence on the CPU-IOMMU. Compared with the SOTA Trans-FW design, WaferTrans improves performance by 2.5x on average.

## 1. 核心问题与整体含义（研究动机与背景）

### 背景
- **统一内存（Unified Memory, UM）的扩展需求**：现代GPU系统通过汇聚更多设备以实现近线性扩展，要求远程数据访问接近本地访问成本，这需要设备间互连带宽达到与本地内存带宽相当的水平（约 (N-1)/N ≈ 1）。
- **现有平台的不足**：以 NVIDIA B200 为例，提供 8 TB/s 内存带宽但仅 0.9 TB/s 互连带宽，互连-内存比为 0.225，无法支持理想的统一内存性能扩展。
- **晶圆级 GPU（WSG）的机遇**：借助 CoWoS 等先进封装技术，WSG 在晶圆级中介层上集成多个 GPU 裸片，提供低延迟、高带宽且统一的片内互连。片上带宽可达 7.5 TB/s（单向），使互连带宽比超过 1，为近无损统一内存提供了物理基础。

### 核心问题
- **CPU-IOMMU 集中式翻译成为瓶颈**：现有系统仍依赖 CPU 端的 IOMMU 作为集中式地址翻译引擎，其问题包括：
  - 每次远程翻译请求必须两次穿越晶圆到 CPU 的链路，跨越多层互连层级，导致高延迟与拥塞；
  - CPU 集成到同一晶圆在工艺和封装上不可行，加剧了层级跨越问题；
  - 传统节点通常为 1 个 CPU 配 8 个 GPU，而单个晶圆可集成 16–32 个 GPU 裸片，GPU 数量增长导致远程访问和翻译请求剧增，CPU 侧 IOTLB 容量和 PTW 并行度均有限；
  - Trans-FW 虽在 CPU-IOMMU 处增设转发表将请求引导至持有目标页表项（PTE）的 GPU，但仍无法消除片外传输，且集中式转发表一次只能处理一个请求，在高并发下成为新的瓶颈。

### 关键观察与核心见解
- PTE 并非缺失，缺失的是**有效定位 PTE 的机制**——能够持有目标 PTE 的 GPU 本身已在阵列内，但缺少一种高效的方式将其找到；
- 若每个 GPU 都能在阵列内高效定位任意请求的 PTE，则远程翻译可完全在 GPU 阵列内部解决，无需依赖 CPU-IOMMU。

## 2. 方法论：核心思想与关键技术

### 整体架构：WaferTrans — 无 IOMMU 的分布式虚拟地址翻译

WaferTrans 的核心思路是将地址翻译从 CPU 侧集中式引擎**解耦**，使 GPU 阵列能够合作解析翻译请求，实现 IOMMU-free 的虚拟地址翻译。

### 关键组件与技术

#### (1) PTE 存在一致性（PTE Presence Consistency, PTE-PC）
- **轻量级一致性模型**：相比完整的 PTE 复制，PTE-PC 只维护紧凑的 PTE 存在性元数据（该 PTE 是否存在于域内、由哪个 GPU 持有），而非 PTE 内容本身。
- **简化的跟踪范围**：GPU 从不直接修改 PTE 内容，PTE 更新仅由页面分配和迁移事件产生。因此只需跟踪两类操作：
  - **插入**：PTE 进入域时；
  - **移除**：PTE 离开域时。
- 相比传统内存一致性模型，该模型实现复杂度大幅降低。

#### (2) PTE 存在目录（PTE Presence Directory, PPD）
- 由 Trans-FW 的转发表改进而来，但**从 CPU 端的集中式单元复制到每个 GPU**（域内复制）。
- PPD 对原始布谷鸟过滤器（cuckoo filter）进行了扩展：以 **VPN + GPU ID 拼接**作为键值。
- 查找时，PPD 使用同一 VPN 与所有可能的 GPU ID 并行探测多条通道。若所有通道均未命中，则 PTE 不在该域内；若命中，则匹配通道直接识别出持有该 PTE 的 GPU。

#### (3) 域存在广播器（Domain Presence Broadcaster, DPB）
- 每个 GPU 配一个 DPB，管理 N 位域成员寄存器（bitmask）。
- 当前 PTE-PC 域内的 M 个 GPU 位置 1，其余 N−M 位清零。
- PTE 更新时，DPB 封装更新信息与 GPU ID，生成本地广播消息发送至所有域成员，接收方刷新其本地 PPD。

#### (4) 分布式 PTE-PC 映射
- **动机**：若构建单一全局 PTE-PC 域，每次更新需在整个网格广播，导致 N×N GPU 阵列的芯片级 NoC 流量激增且每 GPU 需维护 O(N²) 规模的存在元数据，成本过高。
- **策略**：将 GPU 阵列划分为**多个存在域（presence domains）**。例如在 4×4 阵列中，同色 GPU（如 {G1, G3, G9, G11}）构成一个域，PTE 更新仅在对应域的环上传播。
- **交错映射**：映射方式刻意交错设计，以支持通过第二层结构——**本地搜索组（Local Search Group, LSG）** 进行高效查找。
  - 每个 LSG 包含来自每个存在域的至少一个 GPU（例如 {G10, G11, G14, G15}）；
  - 因此一个 LSG **在集合层面完整覆盖了整块晶圆的 PTE 存在信息**，替代了原先 CPU-IOMMU 所承担的查找角色。

#### (5) 协作查询流程（翻译示例）
以图 5(b) 中 GPU G15 错过本地查找为例：
1. **本地域未命中**：G15 首先在本地查找 PTE 失败；
2. **LSG 内搜索**：G15 向同 LSG 的邻近成员 {G10, G11, G14} 广播查询请求；
3. **命中与转发**：假设目标 PTE 在 Domain #1 的 G0 上，G10 的 PPD 命中并将翻译请求转发至 G0；
4. **PTW 返回**：G0 将翻译结果返回给 G15。

整个过程中，翻译请求**完全在晶圆内完成**，无需离开晶圆访问 CPU-IOMMU。

### 设计总结
WaferTrans 通过以下三方面协同实现无 CPU-IOMMU 翻译：
- 分布式存在元数据而非完整 PTE 复制 → 降低存储与一致性开销；
- 域内广播维护 + LSG 内搜索查找 → 兼顾更新开销的局部性与查找覆盖的完整性；
- 片内分布式解析 → 消除片外传输延迟与集中式瓶颈。

## 6. 主要结论与发现

1. **CPU-IOMMU 是 WSG 的性能瓶颈**：远程访问延迟中，IOMMU 等待和晶圆-CPU 传输分别占平均 49% 和 13% 的时间。
2. **晶圆内分布式翻译可行**：通过 PTE-PC 模型与 PPD/DPB 硬件支持，GPU 阵列可完全在晶圆内解析远程翻译，无需 CPU 参与。
3. **显著性能提升**：相比 Trans-FW，WaferTrans 平均加速 **2.5x**。其中 Scatter-Gather 与 Random 负载平均加速达 **3.1x**（此类负载远程访问更频繁）。
4. **局部性强的工作负载差异小**：Sequential 与 Adjacent 类负载数据局部性强、远程访问少，两方案性能差异有限（收益 1.0x–1.16x）。
5. **网络开销可控**：WaferTrans 引入的额外流量（PTE 更新 + PTE 搜索）仅占平均网络流量约 23%，而基线中晶圆-CPU 链路承担的平均流量为平均链路的 1.9 倍，是主要瓶颈。
6. **硬件开销极低**：28-nm 工艺综合面积 0.0354 mm²，功耗 6.011 mW；相对 4 MB L2 缓存面积开销仅 0.40%。
7. **容量需求降低**：通过分布式存储 PTE 位置元数据，WaferTrans 以约为 Trans-FW **1/4** 的表容量即可达到更高的饱和性能（RandomAccess 为例：1,024 vs 4,096 slots）。

## 7. 优点

1. **直击核心瓶颈**：精准识别了 WSG + UM 场景下 CPU-IOMMU 的集中式瓶颈，并提出了系统性解决方案。
2. **问题分解清晰**：将 PTE 内容与 PTE 位置区分开，论证了只需跟踪“谁持有 PTE”而无需完整复制 PTE，极大地简化了问题。
3. **轻量级一致性设计聪明**：利用 GPU 不直接修改 PTE 的特性，将一致性维护简化为仅跟踪插入和删除两类操作。
4. **域 + LSG 双层设计优雅**：域内广播保证更新局部性与存储成本可控，LSG 提供全网覆盖的查找能力，巧妙地平衡了维护成本与查找完整性，避免了全局广播的 O(N²) 代价。
5. **硬件开销极小**：0.40% 面积开销即可消除片外翻译路径，实用性较强。
6. **实验数据多点验证**：性能结果有延迟分解、网络流量归因和容量敏感性等多角度佐证，并非单一性能对比。

## 8. 不足与局限

### 实验覆盖
- 仿真规模缩减为 MI100 的 1/4，可能无法完全反映真实 GPU 的微架构行为；
- 使用的是 16-GPU（4×4）配置，未验证 32-GPU 或更大晶圆阵列的可扩展性趋势；
- 容量敏感性仅覆盖 FFT 与 RandomAccess 两个工作负载，代表性有限。

### 偏差风险
- 模拟中已移除集中式 vm.PageTable，但基线 Trans-FW 依赖 CPU-IOMMU 的完整模拟参数是否完全准确、是否最优化配置有待进一步验证；
- 页面迁移频率在不同工作负载间差异较大，论文未系统分析迁移频率对 PTE 更新流量的影响及其边界条件。

### 应用限制
- 适用于有高带宽、低延迟片上互连的 WSG 架构；对传统 multi-GPU 系统不具备直接适用性；
- 分布式查找增加了 NoC 上的搜索流量，在极高请求速率下 LSG 中的单个 GPU 可能成为新的局部热点，论文对此未做详细分析；
- 假设 PTE 更新仅由页面分配与迁移产生，且 GPU 从不直接修改 PTE——若未来 WSG 支持更灵活的页级操作（如细粒度内存管理），该模型可能需要扩展；
- 论文为 4 页短文，设计细节（如 PPD 的替换策略优化、失败回退机制）不够深入。

### 其他
- DPB 广播消息的处理延迟、PPD 假阳性率（<0.39%）在实际负载中造成的额外开销未能深入量化。
